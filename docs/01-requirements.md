# 需求与成功标准

## 用户与问题

用户是内容运营人员。其需要围绕指定主题，在预算与截止时间内取得一份可交接的活动方案，而不是只收到几段文案。规划期间可能遇到报价太高、素材不足或业务工具失败。系统必须说明实际推进到哪一步，保留能复用的结果。

用户在本次对话中选择了题目“内容任务规划 Agent”，要求实现全部必须验收点：正常完成、缺预算或截止时间、工具失败、预算超限、重复执行，并争取失败步骤续跑。

## 范围

输入主题、模拟预算、带时区的截止时间，可选首选档位。合成素材库有 primary 与 archive 两个来源；方案档位为 12、8、4 SIM。业务工具为本地函数，模型可通过真实 Chat Completions 原生函数调用选择动作。没有模型服务时提供显式离线 Mock。

交付内容包括任务依赖、当前步骤状态、工具参数及实际返回、脚本、费用账本、保存的方案，或明确的未完成原因。活动方案保存成功才算 Agent 完成；方案中的制作、人工审核和发布仍按 planned/pending 标记。

本项目不执行真实发布、广告投放、支付、素材版权采购或生产视频。脚本由本地模板和模型给出的创意角度组合，内容质量不属于本次已验证结论。

## 验收表

| 验收点 | 可核验的成功标准 |
| --- | --- |
| 正常完成 | 预算 20、时间充足，保存 premium；账本 2＋10＝12，四个 Agent 步骤成功 |
| 缺预算 | `needs_input`，指出 budget，模型/工具调用均为 0 |
| 缺截止时间 | `needs_input`，指出 deadline，不擅自补时间 |
| 工具失败 | 注入 primary 一次失败，保留真实错误，改用 archive；失败不得记为成功 |
| 超预算可降级 | 预算 10；premium 估算 12 被拒，再估 standard 8 并保存；不得生成超预算 premium 脚本 |
| 超预算无解 | 预算 3，最低方案 4；不保存，给出至少 1 SIM 缺口 |
| 重复执行 | 同输入同 DB 二次执行重放；Trace、费用、方案数不增加 |
| 失败续跑 | 保存失败后退出；再次 `--resume` 复用素材与脚本，只补保存，最终费用不重复 |
| 部分成功 | 一条 primary 素材保留，再从 archive 补充；原始 partial 记录保留 |
| 截止时间约束 | 20 分钟窗口选择图文档位，10 分钟窗口明确无解 |
| 决策上限 | 达到上限返回 incomplete / STEP_LIMIT，保留状态，不能伪造完成 |
| 模型驱动 | 真实模型返回工具选择，工具观察回传后产生不同的后续动作；至少两条成功实际路径才可判定效果得到验证 |

最后一项目前**实现了接入，但效果尚未验证**，原因是当前服务额度/凭据不可用。其他条目由固定规则离线策略和工程测试验证，不能以此替代模型决策验收。

## 业务口径

预算是模拟业务预算，涵盖成功脚本费用与已保存方案的制作预留，不包含外部模型 API 真实账单。所有计费项以整数分存储。方案切换时已有脚本费用不退回；失败调用免费。时间是可配置业务参考时钟加模拟工具耗时，保存前再次校验，制作完成时间为计划值，不是实际制作成功证明。
